# OPES HealthCore — Clinical Workflow Master Register (30-Domain Audit)

> **Clinical & Regulatory Governance Notice:** OPES HealthCore is a reusable technical healthcare SDK, **not** a standalone medical device or locally certified hospital deployment. Automated tests verify technical state transitions, concurrency safety, tenant isolation, and replay idempotency. Local clinical protocols, drug-formulary rules, critical panic-value thresholds, triage acuity policies, and regulatory sign-offs (ISO 15189, WHO GMP, Ministry of Health, HIPAA/GDPR) **must be reviewed and approved by local clinical governance before production clinical use**.

## Classification Legend
| Classification | Meaning |
|---|---|
| `EXISTING AND VERIFIED` | Implemented in HealthCore starter(s), wired via Liquibase/JPA/auto-configuration, and backed by automated tests. |
| `EXISTING BUT INCOMPLETE` | Core module/entities exist; extended additively or requires consumer-specific external integration adapter (e.g., live SMS carrier, PACS broker, national HIE endpoint). |
| `DUPLICATED` | Competing implementation detected across modules; canonical SDK owner designated while preserving legacy host callers without deletion. |
| `NOT PRESENT` | Not yet implemented as a standalone starter; tracked for roadmap without fabricating implementation. |
| `NOT APPLICABLE` | Outside reusable SDK scope (facility-owned local policy or third-party vendor runtime). |
